# Cinder

A Minecraft Java Edition server written in [Bend](https://github.com/bendlang/bend):
dependently typed, affine, compiled to C, parallel on every CPU core.

Cinder is a competitor to [Pumpkin](https://pumpkinmc.org/). Pumpkin rewrote the
server in Rust; Cinder goes further: the worldgen is a vanilla 26.2 overworld
pipeline — biomes, the `overworld.json` density graph, aquifers, ore veins,
surface rules, carvers and the feature stage — ported from the decompiled
sources and verified block-by-block against reference worlds generated by the
real vanilla server. Packet codecs are pinned by `LAWS.bend` so the compiler
rejects edits that break VarInt framing.

## Parity

Measured against vanilla 26.2 worlds generated by the real server on this machine
(seed 1), comparing every block position in the compared chunks
([`bench/WORLD.md`](bench/WORLD.md) has the method and the full breakdown).

| Reference | Area | Block agreement |
| --- | --- | ---: |
| features and structures disabled | 8×8 chunks (16..23 × 8..15) | **100.000000 %** (6 291 456/6 291 456) |
| features and structures disabled | 32×32 = 1024 chunks | 99.999506 % |
| **canonical (everything on)** | 8×8 chunks | **98.099534 %** (6 171 889/6 291 456) |

Biomes are 100 % in every comparison. The remaining canonical-world gap is 66 %
missing structures (`trial_chambers`, 229 jigsaw pieces), then ~16 200 leaf
positions and ~9 000 ore/vein positions. The primitives under all of it —
density functions, noise, biome sampling, carver masks, the feature RNG — are
bit-identical to the jar, checked by `bench/parity/df_check.sh`,
`noise_check.sh`, `carve_diff.py`, `check_feature_order.py` and `RngProbe.java`.

## 1024 Full chunks: Cinder vs Pumpkin vs Folia vs C2ME

Same machine (Ryzen 7 5700G, 8c/16t), same target: 1024 chunks (32×32), same
question — how long until 1024 chunks of block data exist? Cinder and Pumpkin
generate in memory; Folia and C2ME write Anvil and boot a JVM first, so they also
appear on the "spawn → 1024 chunks" row, which is what a player waits for.

| Engine / config | 1024-chunk gen | per chunk | spawn → 1024 | notes |
| --- | ---: | ---: | ---: | --- |
| **Cinder** 1 thread | 96.65 s* | 94.4 ms | — | |
| **Cinder** 4 threads | 27.78 s* | 27.1 ms | — | |
| **Cinder** 8 threads | 19.90 s | 19.4 ms | 20.2 s | |
| **Cinder** 16 threads | **16.12 s** | 15.7 ms | **15.1 s** | best 15.27 s |
| Pumpkin 1 thread | 24.14 s | 23.6 ms | — | |
| Pumpkin 4 threads | 7.17 s | 7.0 ms | — | |
| Pumpkin 8 threads | 4.88 s | 4.8 ms | ~5.2 s | gen, then boot |
| Pumpkin 16 threads | 5.10 s | 4.7 ms | — | flattens after 8 |
| C2ME 0.4.2-α, 8 workers | 8.62 s | 8.4 ms | 21.6 s | Fabric + Lithium, Anvil |
| Folia 26.2-7, 8 workers | 11.9 s | 11.6 ms | 23.3 s | Moonrise, Anvil |
| **Cinder GPU** | 59.2 s† | 0.90 ms† | — | † microbench, see below |

\* earlier build from the same session (before the tree fix and the decorated
halo, which cost ~13 % at 8 threads).

**Pumpkin is 4.08× faster than Cinder at 8 threads** and 3.15× at 16 threads.
Cinder beats both Java servers on time-to-world (15.1 s against C2ME 21.6 s and
Folia 23.3 s) even though those numbers include a JVM boot and disk writes and
Cinder's do not. Where Cinder's 20.1 s @ 8 threads goes: terrain 3.13 s,
surface rules +11.34 s, carvers +0.41 s, features +5.19 s.

### The GPU row

† **Not the same work.** Cinder's generator is C behind one IO effect, so it is
not a GPU target: Bend only hands `!` (parallel call) to the device, and nothing
in the pipeline uses it. The row above is Bend's heightmap microbench
(`src/world.bend`, `World.grid!`) at 65 536 chunks — the same code, same
checksum, run both ways:

| Heightmap microbench | CPU 8 threads | GPU `--gpu 4GB` | speedup |
| --- | ---: | ---: | ---: |
| 32×32 chunks | 19 ms | ~2.4 s | 0.008× (device fixed cost dominates) |
| 256×256 = 65 536 chunks | 113.6 s | **59.2 s** | **1.92×** |

Both modes produce identical checksums (16647010 and 1065330270). See
[`bench/WORLD.md`](bench/WORLD.md#gpu) for the toolchain, the WSL2 caveat and the
per-chunk normalisation.

## Bend vs C

The server is Bend; the generator is C, reached through one
`import "./vanilla_gen.c"` in `src/world.bend`. `scripts/language_audit.py` prints
the split: Bend 1 068 lines (2.6 % of the tree), C 13 630 plus 9 366 lines of
headers, Python/Shell tooling 8 144, JSON data 7 826. `bench/BEND.md` records what
moving the generator into Bend would take, measured against bend 2.0.5's type
system.

## Build

Bend does not run on native Windows (its runtime is POSIX: pthreads, unistd,
mmap; the compiler has no `_WIN32` branch). Use WSL or Linux.

```bash
curl -fsSL https://bend-lang.com/install.sh | sh
cd cinder

# point the C modules' absolute sibling includes at your checkout (see AGENTS.md)
python3 scripts/relocate.py

# worldgen JSON: extract once from your own 26.2 server jar
python3 scripts/extract_vanilla_worldgen.py

# unit tests (checker, no IO)
bend tests/codec.bend    # 11111111
bend tests/world.bend    # 1111
bend tests/proto.bend    # 1111
bend PROOF.bend          # all terms check

# native server (clang 14+)
bend src/main.bend -o cinder
./cinder --threads 8

# 1024-chunk worldgen bench
bend src/bench.bend -o cinder-bench
./cinder-bench --threads 8
scripts/bench_cinder_worldgen.sh 4 8 16     # medians of 3 runs per thread count

# GPU target (clang 19+; CUDA 12 at /usr/local/cuda)
bash bench/parity/gpu_probe.sh              # toolchain + device + both runs
bash bench/parity/gpu_run.sh src/gpu_bench.bend
```

Ping without a Minecraft client: `python3 scripts/ping.py 127.0.0.1 25565`.

Head-to-head vs Pumpkin: `python3 scripts/world_bench.py` (writes
[`bench/PUMPKIN.md`](bench/PUMPKIN.md)).

## Protocol

Target: **Java Edition 26.2, protocol 776**. Offline mode, no compression, no
encryption. Status JSON is hand-built (Bend has no JSON library). Chunk packets
to players and entity simulation are the next slice of work — the Full-chunk
generator is already the hot path those packets will use.
